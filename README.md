# ☕ منوی دیجیتال کافه — نسخه‌ی سه‌بعدی

یک وب‌اپ موبایل‌محور برای نمایش منوی کافه با ظاهر سه‌بعدی، پنل مدیریت و تولید QR کد.
**بدون سبد خرید، بدون ثبت سفارش و بدون پرداخت** — فقط نمایش منو و قیمت.

## ۱) پیش‌نیازها

- **Node.js نسخه‌ی ۲۲ یا بالاتر** (برای سازگاری با وابستگی‌های فعلی؛ Node.js 22 LTS پیشنهاد می‌شود) — [nodejs.org](https://nodejs.org)
- npm (همراه Node نصب می‌شود)

بررسی:

```bash
node -v    # باید v22 یا بالاتر باشد
npm -v
```

## ۲) اجرای محلی (۳ دستور)

```bash
cd cafe-menu
npm install      # نصب وابستگی‌ها
npm run dev      # اجرای سرور توسعه
```

سپس در مرورگر باز کنید:

- منوی مشتری: `http://localhost:5173/`
- پنل مدیریت: `http://localhost:5173/admin`
- **رمز پیش‌فرض پنل (فقط حالت محلی/توسعه):** `cafe1404` — روی Cloudflare از Secret `ADMIN_PASSWORD` استفاده می‌شود

### اجرای راحت و دسترسی از شبکه‌ی محلی ویندوز

در ویندوز، `start-cafe-menu.bat` را اجرا کنید. بار اول یک پورت وارد کنید (پیش‌فرض 5173)؛ پورت در `.cafe-menu-port.txt` ذخیره می‌شود. اجراهای بعدی می‌پرسند از پورت ذخیره‌شده استفاده شود یا پورت جدید. همان پورت هم به Vite داده می‌شود و هم در فایروال برای `LocalSubnet` مجاز می‌شود.

BAT وابستگی‌ها را خودکار نصب و سرور را شروع می‌کند. در بار اول یا هنگام تغییر پورت، Windows یک‌بار تأیید Administrator (UAC) می‌خواهد؛ این تأیید امنیتی را نمی‌توان بدون کلیک کاربر دور زد. Node.js 22 یا بالاتر باید از قبل نصب باشد. آدرس گوشی روی همان Wi-Fi در پنجره چاپ می‌شود. از Guest Wi-Fi استفاده نکنید و VPN/Client isolation روتر را بررسی کنید. فایل BAT مخصوص Windows است.

> تست‌ها: `npm test` (۶۳ تست — منطق منو، قالب قیمت، مشتری، چیپ‌های دسته‌بندی، ادمین، تم‌ها/صحنه‌ها، RLS/Supabase، Cloudflare و فایل‌های bat)
> بیلد تولید: `npm run build` و پیش‌نمایش بیلد: `npm run preview`

## ۴) شخصی‌سازی سریع

**نام کافه، شعار و ساعت شروع/پایان** را از پنل `/admin` ← «تنظیمات» تغییر دهید؛ این موارد در سربرگ/کارت خوش‌آمدگویی و پاورقی منوی مشتری به‌روز می‌شوند. در همان صفحه، کارت‌های دیداری تم را انتخاب کنید: کلاسیک، نوروز، یلدا، رمضان، روز عشق، پاییز، هالووین، کریسمس و روز مادر. انتخاب تم فوراً در منوی مشتری اعمال می‌شود. هر تم صحنه‌ی SVG، ذرات متحرک، دکور بالای صفحه و تصویر داخل کارت خوش‌آمدگویی مخصوص خودش را دارد (یاقوت: گوهر تراش‌خورده، مخمل و زنجیر طلا؛ هالووین: ماه خونین، خفاش، خانه‌ی ارواح، چکه‌ی خون و تار عنکبوت؛ روز عشق: برج ایفل و بام‌های پاریس؛ رمضان: فانوس و مسجد؛ …). تم‌های شبانه (هالووین، رمضان، یلدا، کریسمس) همیشه تیره‌اند و دکمه‌ی روشن/تاریک برایشان مخفی می‌شود. برای افزودن تم تازه: یک ورودی در `src/lib/themes.js`، یک صحنه در `src/components/scenes/` و یک بخش در `src/styles/themes.css`. این اطلاعات فعلاً در همان مرورگر ذخیره می‌شوند؛ برای استفاده روی چند دستگاه، اتصال به بک‌اند لازم است.

مقدارهای اولیه و لوگو در `src/data/cafe.json` قرار دارند؛ مانند `name`، `openingTime`، `closingTime` و `festivalTheme`. تنظیمات ذخیره‌شده‌ی پنل بر مقدارهای اولیه اولویت دارند.

**منوی اولیه** — `src/data/menu.seed.json` را ویرایش کنید (یا از پنل ادمین استفاده کنید).
ساختار هر آیتم:

```json
{ "id": "i-1", "name": "کاپوچینو", "desc": "…", "price": 128000,
  "emoji": "🥛", "image": "", "available": true, "tags": ["پرطرفدار"] }
```

**رنگ‌ها** — متغیرهای بالای `src/styles/global.css` (`--brand`, `--accent`, `--bg`, …).
نسخه‌ی تاریک زیر `[data-theme='dark']` تعریف شده است.

## ۵) کار با پنل ادمین

مسیر `/admin` → رمز عبور (پیش‌فرض `cafe1404`).

1. **گروه‌ها و اقلام** — افزودن/ویرایش/حذف گروه، جابه‌جایی با ▲▼، افزودن آیتم به هر گروه،
   ویرایش نام/توضیح/قیمت/ایموجی/عکس، تغییر وضعیت موجود-ناموجود، و جابه‌جایی آیتم‌ها.
2. **QR کد** — QR اصلی منو + QR جداگانه برای هر میز؛ دانلود PNG و چاپ.
3. **تنظیمات** — دانلود/وارد کردن JSON، بازگردانی منوی نمونه، تغییر رمز عبور، خروج.

- تغییرات **بلافاصله و خودکار** ذخیره می‌شوند و در منوی مشتری دیده می‌شوند
  (اگر منو در تب دیگری باز باشد، همان لحظه به‌روز می‌شود).
- **عکس آیتم:** یا لینک تصویر، یا «آپلود عکس» — تصویر به‌طور خودکار به حداکثر ۴۸۰px
  کوچک می‌شود تا حجم داده زیاد نشود.
- **رمز عبور** را از تب تنظیمات عوض کنید.

## ۶) QR کد و شماره‌ی میز

- QR اصلی به آدرس منو اشاره می‌کند. بعد از انتشار، آدرس واقعی را در فیلد
  «آدرس منو» بگذارید و دوباره QR بگیرید.
- با ورود شماره‌ی میزها (مثلاً `1-6` یا `۱،۳،۷`) برای هر میز یک QR ساخته می‌شود که
  آدرسش `…/?t=5` است؛ در نتیجه بالای منوی مشتری نشان «میز ۵» نمایش داده می‌شود.
- دکمه‌ی **چاپ** با استایل چاپ (`@media print`) کار می‌کند: پس‌زمینه و منوهای ادمین
  چاپ نمی‌شوند و فقط برگه‌های QR روی کاغذ می‌روند.

## ۷) داده‌ها کجا ذخیره می‌شوند؟

حالت پیش‌فرض (بدون `.env.local`) از **localStorage همان مرورگر** استفاده می‌کند؛ منو با کلید `cafe-menu:data:v1` و مشخصات کافه/تم با `cafe-menu:cafe:v1` ذخیره می‌شوند. این حالت ساده و سریع است، اما تغییر ادمین به دستگاه دیگر منتقل نمی‌شود.

برای همگام‌سازی لپ‌تاپ و گوشی، Supabase را طبق مراحل زیر تنظیم کنید:

### الف) استفاده از فایل JSON (ساده، بدون بک‌اند)

در ادمین: **تنظیمات ← دانلود منو (JSON)**، سپس محتوای `src/data/menu.seed.json` را با آن
عوض کنید و دوباره بیلد/منتشر کنید.

### ب) Supabase برای همگام‌سازی واقعی بین لپ‌تاپ و گوشی

تا وقتی فایل `.env.local` با کلیدهای پروژه ساخته نشده، برنامه در حالت محلی (`localStorage`) کار می‌کند. پس از تنظیم Supabase، **منو و اطلاعات کافه** در فضای ابری ذخیره می‌شوند و مشتری‌ها پس از ذخیره‌ی ادمین تغییرات را از Supabase می‌خوانند.

1. در Supabase یک پروژه بسازید. از **Project URL** و **anon/public key** استفاده می‌کنیم؛ کلید `service_role` را هرگز در فرانت‌اند یا Cloudflare نگذارید.
2. در **SQL Editor** محتوای فایل `supabase/setup.sql` را یک بار اجرا کنید. این فایل RLS را طوری می‌چیند که بازدیدکننده‌ها فقط بخوانند و کاربر واردشده بتواند بنویسد.
3. در **Authentication → Users** یک کاربر مدیر بسازید و ثبت‌نام عمومی کاربران را غیرفعال نگه دارید؛ این تنها حسابی باشد که امکان ورود به پنل دارد.
4. از `.env.example` یک کپی به نام `.env.local` بسازید و سه مقدار را پر کنید:

   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
   VITE_SUPABASE_ADMIN_EMAIL=admin@example.com
   ```

5. اجرای مجدد `start-cafe-menu.bat` (یا اجرای مجدد dev server) باعث خواندن تنظیمات می‌شود. در `/admin` همان رمز حساب Supabase مدیر را وارد کنید. تغییر رمز در پنل نیز رمز Auth را تغییر می‌دهد.
6. برای انتشار مستقیم در Cloudflare Pages، فایل `.env.local` باید هنگام build روی همان رایانه موجود باشد تا Vite تنظیمات عمومی Supabase را داخل build قرار دهد. کلید anon عمومی است و با RLS محافظت می‌شود؛ service role محرمانه می‌ماند.

اگر تنظیمات Supabase ناقص باشد، برنامه به localStorage برمی‌گردد؛ این حالت بین دستگاه‌ها همگام نمی‌شود. داده‌های قدیمی localStorage خودکار به ابر منتقل نمی‌شوند: پیش از تغییر حالت، از پنل JSON منو را دانلود کنید؛ پس از فعال‌سازی Supabase وارد پنل شوید و JSON را import کنید تا نسخه‌ی مشترک ساخته شود. فایل‌های `.env*` از Git نادیده گرفته می‌شوند.

## ۸) انتشار

برای روش Cloudflare، فایل `prepare-cloudflare.bat` را اجرا کنید؛ این فایل وابستگی‌ها را در صورت نیاز نصب می‌کند، `npm run build` را اجرا می‌کند و پوشه‌ی `dist` را باز می‌کند. `.env.local` را پیش از build تنظیم کنید تا نسخه‌ی Cloudflare به Supabase وصل شود.

### همگام‌سازی بین همه‌ی گوشی‌ها (خیلی مهم)

منو و اطلاعات کافه روی **API همان Worker** ذخیره می‌شوند (Durable Object / SQLite داخلی
کلادفلر). یعنی هر تغییری که در `/admin` بزنید، روی **همه‌ی گوشی‌ها و مرورگرها** دیده می‌شود —
بدون سرویس خارجی، بدون اکانت اضافه.

```
GET  /api/state   → منو + اطلاعات کافه (عمومی)
GET  /api/meta    → فقط زمان آخرین تغییر (برای polling سبک)
POST /api/login   → بررسی رمز ادمین
PUT  /api/menu    → ذخیره‌ی منو  (هدر x-cafe-key)
PUT  /api/cafe    → ذخیره‌ی اطلاعات کافه و تم (هدر x-cafe-key)
PUT  /api/auth    → تغییر رمز (هدر x-cafe-key)
```

- **لحظه‌ای (WebSocket):** هر دستگاه به `GET /api/live` وصل می‌شود (Durable Object با
  WebSocket Hibernation). با هر `PUT` روی منو/اطلاعات کافه، سرور همان لحظه به همه‌ی
  دستگاه‌ها پیام می‌دهد و صفحه بدون رفرش به‌روز می‌شود (در تست: ~۴۰ میلی‌ثانیه).
- **فالبک:** اگر WebSocket برقرار نشد (شبکه‌ی محدود و…)، هر ۸ ثانیه `/api/meta` پرسیده
  می‌شود؛ با وصل بودن سوکت، polling غیرفعال است. با برگشت به تب یا اتصال اینترنت هم
  بلافاصله همگام می‌شود.
- رمز ادمین روی سرور است، پس ورود از هر گوشی با همان رمز کار می‌کند.
- نوشتن بدون کلید رمز، خطای ۴۰۱ می‌گیرد؛ هش رمز هرگز در پاسخ عمومی برنمی‌گردد.
- **رمز اولیه:** اگر Secret به نام `ADMIN_PASSWORD` تنظیم نشده باشد، رمز پیش‌فرض `cafe1404` کار می‌کند (برای شروع ساده).
  هر کسی که این پیش‌فرض را بداند تا قبل از اولین «تغییر رمز» می‌تواند منو را تغییر دهد؛ پس بعد از اولین ورود، رمز را از پنل عوض کنید.
  اگر خواستید از همان ابتدا امن باشد: `npx wrangler secret put ADMIN_PASSWORD` (یا داشبورد ← Worker ← Settings ← Variables and Secrets ← Secret).
- ورودِ اشتباه برای هر IP محدود است (۸ بار در ۱۵ دقیقه ← `429`)؛ مقایسه‌ی رمز زمان‌ثابت است؛ بدنه‌ی بزرگ‌تر از ۱ مگابایت و بیش از ۳۰۰ اتصال WebSocket رد می‌شود.
- بعد از اولین «تغییر رمز» در پنل، رمز جدید جای Secret را می‌گیرد.
- اگر Worker در دسترس نباشد (مثلاً `npm run dev` بدون wrangler)، برنامه خودکار به حالت
  localStorage برمی‌گردد و خراب نمی‌شود.

**اجرای محلی با API:**

```bash
npm run dev:api                      # ترمینال ۱ — wrangler dev روی 8788
npm run dev                          # ترمینال ۲ — Vite با پروکسی /api (و WebSocket)
```

**تست یکپارچه‌ی همگام‌سازی (دو دستگاه شبیه‌سازی‌شده):**

```bash
npm run dev:api     # در ترمینال دیگر
npm run test:api    # ۱۳ سناریو: API، دو دستگاه، و لحظه‌ای بودن WebSocket
```

> اگر داده‌ای از قبل در حالت محلی ساخته‌اید، بعد از دیپلوی یک بار در
> **پنل → تنظیمات → «ارسال داده‌های این دستگاه به سرور»** را بزنید تا همان منو/تم روی سرور
> نوشته شود.

### Cloudflare Workers (اتصال به GitHub / Workers Builds) — توصیه‌شده

این پروژه با `wrangler deploy` به‌صورت **Worker + Static Assets** منتشر می‌شود. تنظیمات لازم
در فایل `wrangler.jsonc` مخزن وجود دارد:

- `assets.directory: "./dist"`
- `assets.not_found_handling: "single-page-application"` → مسیرهایی مثل `/admin` و هر
  deep link دیگر با رفرش هم `index.html` می‌گیرند.

در داشبورد Cloudflare برای Build:

| فیلد | مقدار |
| --- | --- |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |

> ⚠️ **فایل `public/_redirects` را برنگردانید.** قاعده‌ی `/* /index.html 200` مخصوص
> Cloudflare Pages است و روی Workers با خطای
> `Invalid _redirects configuration: Infinite loop detected in this rule [code: 100324]`
> کل دیپلوی را متوقف می‌کند (چون Workers خودش `.html` و `/index` را نرمال می‌کند).
> فالبک SPA همان `not_found_handling` است.

### Cloudflare Pages — آپلود مستقیم از داشبورد

1. در داشبورد Cloudflare از **Workers & Pages → Create → Pages → Direct Upload** یک پروژه بسازید.
2. فایل `prepare-cloudflare.bat` را اجرا کنید.
3. فایل `deploy/cloudflare-pages/_redirects` را داخل پوشه‌ی `dist` کپی کنید (فقط برای Pages لازم است).
4. **محتویات پوشه‌ی `dist`** را در صفحه‌ی آپلود Pages بکشید و منتشر کنید؛ خود پوشه‌ی سورس را آپلود نکنید.
5. Cloudflare یک آدرس `pages.dev` می‌دهد؛ مسیر `/admin` هم به `index.html` برمی‌گردد.

برای هر تغییر بعدی، دوباره `prepare-cloudflare.bat` را اجرا و build جدید `dist` را آپلود کنید. خود BAT نمی‌تواند بدون کلیک/انتخاب در داشبورد Cloudflare پروژه را منتشر کند.

### هاست اشتراکی (cPanel و مشابه)

1. `npm run build`
2. محتویات `dist/` را در `public_html` آپلود کنید.
3. در `.htaccess` این قانون را بگذارید تا `/admin` کار کند:

   ```apache
   RewriteEngine On
   RewriteBase /
   RewriteRule ^index\.html$ - [L]
   RewriteCond %{REQUEST_FILENAME} !-f
   RewriteCond %{REQUEST_FILENAME} !-d
   RewriteRule . /index.html [L]
   ```

## ۹) نکات عملکرد (گوشی ضعیف)

- **پس‌زمینه:** به‌جای Three.js از یک Canvas دوبعدی با «عمق» استفاده شده؛ دانه‌ها یک‌بار
  روی اسپرایت پیش‌رندر می‌شوند، پس در هر فریم فقط `drawImage` اجرا می‌شود. تعداد دانه‌ها
  بر اساس عرض صفحه و `hardwareConcurrency` تنظیم می‌شود، با مخفی‌شدن تب متوقف می‌شود،
  و با `prefers-reduced-motion` کاملاً بی‌حرکت می‌شود.
- **تیلت کارت‌ها** بدون `setState` و مستقیم روی DOM اعمال می‌شود (بدون ری‌رندر در هر فریم).
- **پنل ادمین و کتابخانه‌ی QR** با `React.lazy` جدا بارگیری می‌شوند؛ مشتری فقط
  ~۱۴۰KB (gzip) جاوااسکریپت دانلود می‌کند.
- انیمیشن‌ها فقط `transform` و `opacity` هستند (بدون انیمیشن `height/top/left`).

## ۱۰) امنیت (مهم)

در حالت localStorage، رمز پنل فقط در مرورگر بررسی می‌شود و امنیت واقعی نیست. در حالت Supabase، ورود مدیر از Supabase Auth انجام می‌شود و RLS فقط خواندن عمومی و نوشتن **ایمیل مدیر** را مجاز می‌کند (تابع `is_cafe_admin()` در `supabase/setup.sql`؛ پیش از اجرا `admin@example.com` را با ایمیل واقعی عوض کنید). در Supabase ثبت‌نام عمومی را هم خاموش کنید. کلید anon در فرانت‌اند عمومی است؛ هرگز کلید `service_role` را در پروژه‌ی React یا Cloudflare قرار ندهید.
